# 代码设计逻辑

## 日历格子生日匹配

日历格子生日匹配：现在有一个按阳历年缓存的 birthdayIndexByYear：每次显示年份变化时，会预计算 currentYear - 1 / currentYear / currentYear + 1，同时包含“即将到来的生日”需要的今天所在年和三个月后所在年。农历生日会尝试 solarYear - 1 / solarYear / solarYear + 1 三个农历年，只保留实际落在该阳历年的 occurrence，所以腊月三十落到次年 1/2 月的情况可以正确显示。

## 跨年的即将到来的生日能显示正常

现在的逻辑能覆盖“12 月底看跨年后生日”的关键点在于：**即将到来的生日不是只算当前年份，而是按一个真实的未来时间窗口查索引**。

流程是这样的：

1. 先确定提醒窗口  
   比如今天是：

   ```text
   2026-12-25
   ```

   系统会算出：

   ```text
   today = 2026-12-25
   threeMonthsLater = 2027-03-25
   ```

2. 收集这个窗口涉及的阳历年份  
   这里会得到：

   ```text
   [2026, 2027]
   ```

   所以不会只看 2026 年，也会把 2027 年的生日索引拿进来。

3. 每个阳历年索引里已经预先算好了农历生日对应的真实阳历日期  
   例如某人生日是农历腊月三十。

   如果它在 2027 年 2 月某天出现，那么它会被存进：

   ```text
   2027 年索引
   ```

   里面的 key 类似：

   ```text
   2027-02-05
   ```

4. 即将到来的生日会把 2026 和 2027 两个年份的索引展开，然后过滤：

   ```text
   solarDate >= 2026-12-25
   solarDate <= 2027-03-25
   ```

   所以只要生日真实发生在这个区间内，就会显示。

也就是说，跨年能正常显示的原因是：**判断依据不是“生日属于今年还是明年”，而是“这个生日实际换算出来的阳历日期是否落在未来三个月内”。**

## 输入合法性

对，可以这么定，而且这比把年份参与日期合法性判断更合理。

你的数据模型里生日其实分两层：

```text
生日规则：月 + 日 + 阳历/农历
出生年份：可选，只用于显示年龄
```

所以年份不应该影响“这个生日是否保存”。它只应该影响“能不能算岁数”。

我建议规则这样定：

### **月份和日期必须合法**

阳历：

```text
月份：1-12
日期：必须是该月存在的日期
```

也就是：

```text
1/31 合法
2/29 合法
2/30 非法
4/31 非法
13/1 非法
```

这里阳历 `2/29` 应该允许，因为它是合法生日，只是在非闰年不显示，或者未来你可以定义显示策略。

农历：

```text
月份：1-12
日期：1-30
```

农历不要按某个年份判断，比如腊月三十有些年没有，但这个生日规则本身是合法的。

### **年份只做轻校验**

年份可空。

如果填写了：

```text
必须是数字
必须 <= 当前年份
建议 >= 1900 或 >= 1，看你想不想限制历史范围
```

我建议实际产品里用：

```text
1900 <= 年份 <= 当前年份
```

如果你想更宽松，也可以：

```text
1 <= 年份 <= 当前年份
```

但 0001 年这种对生日应用没意义。

### **年龄计算**

如果年份为空：

```text
不显示年龄
```

如果年份存在：

```text
显示 当前生日实际发生年份 - 出生年份
```

你现在重构后用的是 `nextDate.getFullYear() - birthday.year`，这个方向是对的。

不过严格讲，这只是“周岁/虚岁”之外的一个简单年龄显示：

```text
今年生日发生年份 - 出生年份
```

对于“即将到来的生日”，这个显示是合理的：

```text
2027 年过生日，出生年 2000 -> 27 岁
```

### **不建议的事情**

不要让年份参与阳历生日合法性：

```text
出生年 2001，生日 2月29日
```

如果你强校验出生年，那它会变成非法。但用户可能只是想记录“每逢 2月29日过生日”的规则。除非你明确要做出生日期真实性校验，否则没必要。

也不要保存非法月日然后“不显示”。这会让数据变脏。

最终建议：

```text
保存时强校验 calendar + month + day
year 可选；填了只要求 <= 当前年份
year 不参与生日日期规则
```

这是最稳的边界。
